# LOCAL:ON Route Recommendation

LOCAL:ON은 지역별 **로컬발견가능성**과 장소별 **현지인·외지인 순위 데이터**를 기반으로  
맛집, 관광지, 카페·베이커리를 조합하여 실제 여행 경로를 추천하는 모델입니다.

단순히 인기 장소를 나열하는 것이 아니라,

**지역 추천 → 장소 후보 선정 → 이동거리·시간대·카테고리 다양성 고려 → 최종 경로 생성**

의 흐름으로 동작합니다.

## 1. Recommendation Flow

```text
사용자 시도 선택
        ↓

        ↓

        ↓

        ↓
최종 여행 경로 생성

4. Place Recommendation Score

장소 추천점수는 현지인 순위와 외지인 순위를 점수로 변환하여 계산합니다.

현지인 점수

현지인 순위는 1위 100점부터 100위 50.5점까지
0.5점 간격으로 부여합니다.

현지인점수 = 100 - (순위 - 1) × 0.5
외지인 점수

외지인 순위는 1위 50점부터 100위 0.5점까지
0.5점 간격으로 부여합니다.

외지인점수 = 50 - (순위 - 1) × 0.5
추천점수

현지인·외지인 순위가 모두 존재하는 장소는 두 점수의 평균을 추천점수로 사용합니다.

예시:

현지인 16위
= 100 - (16 - 1) × 0.5
= 92.5점

외지인 23위
= 50 - (23 - 1) × 0.5
= 39.0점

추천점수
= (92.5 + 39.0) / 2
= 65.75점

한쪽 순위만 존재하는 경우에는 존재하는 점수를 추천점수로 사용합니다.

6. Time-based Recommendation

기본 여행 시작시간은 10:00입니다.

시간대 기준
점심 식사: 11:30 ~ 14:00
저녁 식사: 17:30 ~ 20:00
카페·베이커리: 13:00 ~ 17:30
관광지: 오전~오후 방문 우대

예를 들어 당일치기 일정에서 맛집이 오전 10시에 배치되거나,
맛집 두 곳이 연속으로 추천되는 것을 방지하도록 설계했습니다.

7. Route Improvement Logic
7.1 출발지 자동 설정

사용자가 출발 위치를 직접 입력하지 않은 경우, 선택 지역 내 후보 장소들의 위도·경도 중앙값을 임시 출발지로 사용합니다.

이를 통해 첫 번째 장소까지의 이동시간도 경로 최적화에 포함합니다.

7.2 근접 관광지 중복 방지

서로 약 500m 이내에 위치한 관광지는 동일 관광권역으로 판단합니다.

따라서 매우 가까운 관광지가 각각 별도의 일정으로 중복 추천되는 것을 제한합니다.

예:

장항송림산림욕장
장항스카이워크

처럼 동일 권역에 가까이 위치한 관광지가 동시에 일정에 포함되는 문제를 방지합니다.

7.3 관광지 다양성

관광지의 세부분류가 반복될 경우 감점을 적용합니다.

예를 들어 한 일정에 동일한 유형의 관광지만 계속 포함시키기보다는

시장
자연공원
생태관광
웰니스관광

등 다양한 유형의 장소가 포함될 수 있도록 경로를 평가합니다.

10. Kakao Mobility API

Kakao Mobility REST API Key가 설정되어 있을 경우 실제 자동차 이동시간을 경로 최적화에 사용할 수 있습니다.

Windows PowerShell 예시:

$env:KAKAO_REST_API_KEY="YOUR_REST_API_KEY"

API Key가 설정되어 있지 않은 경우 위도·경도를 이용해 이동거리와 이동시간을 추정합니다.

API Key는 Python 코드 또는 GitHub 저장소에 직접 업로드하지 않습니다.
