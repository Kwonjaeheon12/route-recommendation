# LOCAL:ON Route Recommendation

LOCAL:ON은 지역별 **로컬발견가능성**과 장소별 **현지인·외지인 순위 및 추천점수**, 전통시장 데이터를 기반으로 여행 경로를 생성하는 지역 관광 추천 모델입니다.

단순히 인기 장소를 나열하는 것이 아니라,

**지역 추천 → 장소 후보 생성 → 카테고리별 점수 정규화 → 이동거리·시간대·장소 다양성 고려 → 최종 경로 생성**

의 흐름으로 동작합니다.

현재 모델은 다음 장소 유형을 지원합니다.

- 맛집
- 관광지
- 카페/베이커리
- 전통시장

---

# 1. Recommendation Flow

```text
사용자 시도 선택
        ↓
선택 시도 내 시군구 로컬발견가능성 순위 제공
        ↓
사용자 여행 지역 선택
        ↓
여행 카테고리 선택
맛집 / 관광지 / 카페·베이커리 / 전통시장
        ↓
지역별 장소 데이터 JOIN
        ↓
카테고리별 상위 장소 후보 생성
        ↓
카테고리 내부 추천점수 순위 산출
        ↓
경로 최적화용 공통 경로선택점수 계산
        ↓
시간대 + 이동거리 + 관광지 다양성 + 중복 여부 평가
        ↓
최종 여행 경로 생성
```

---

- 전통시장 데이터 직접 활용
- 맛집 / 관광지 / 카페·베이커리 / 전통시장 통합 경로 생성
- 서로 다른 카테고리 간 점수 척도 보정
- 점심·저녁·카페 방문 시간대 반영

## 4.2 `restaurant_score.csv`

음식점의 현지인·외지인 순위를 점수로 변환한 결과를 저장합니다.

주요 컬럼:

- 관광지ID
- 현지인순위

- 현지인점수
- 외지인점수
- 추천점수
- 추천순위

### 현지인 점수

```text
현지인점수 = 100 - (현지인순위 - 1) × 0.5
```

1위는 100점이며 100위는 50.5점입니다.

### 외지인 점수

```text
외지인점수 = 50 - (외지인순위 - 1) × 0.5
```

1위는 50점이며 100위는 0.5점입니다.

### 추천점수

현지인·외지인 순위가 모두 존재하는 경우:

```text
추천점수 = (현지인점수 + 외지인점수) / 2
```

한쪽 순위만 존재하는 경우에는 존재하는 점수를 사용합니다.

# 6. Traditional Market Route Score

전통시장에는 음식점이나 관광지와 동일한 현지인·외지인 순위 데이터가 존재하지 않습니다.

따라서 전통시장 자체의 후보 순위를 정하기 위한 별도의 `시장경로점수`를 계산합니다.

```text
시장경로점수
= 기본점수 50
+ 점포수 규모 최대 30
+ 주차장 보유 10
+ 공중화장실 보유 10
```

점포수는 대형시장 이상치의 영향을 줄이기 위해 `log1p` 변환 후 Min-Max 정규화를 적용합니다.

중요한 점은 `시장경로점수`를 음식점이나 관광지의 추천점수와 직접 비교하지 않는다는 것입니다.

# 8. Place Recommendation Score

LOCAL:ON v5.1에서는 두 종류의 점수를 구분합니다.

---

## 8.1 장소추천점수

각 데이터에서 계산된 원래 장소 추천점수입니다.

용도:

```text
동일 카테고리 내부에서 좋은 장소를 찾는 점수
```

예:

```text
맛집끼리 비교
관광지끼리 비교
카페끼리 비교
전통시장끼리 비교
```

서로 다른 카테고리의 장소추천점수는 계산 기준이 다르기 때문에 직접 비교하지 않습니다.

---

## 8.2 경로선택점수

서로 다른 카테고리를 하나의 여행 경로에서 비교하기 위해 사용하는 공통 점수입니다.

각 카테고리 내부 순위를 기준으로:

```text
1위 = 100점
2위 = 95점
3위 = 90점
4위 = 85점
...
최저 = 55점
```

으로 변환합니다.

즉,

```text
장소추천점수
→ 카테고리 내부 후보 선정을 위한 원래 점수

경로선택점수
→ 서로 다른 카테고리를 경로 안에서 비교하기 위한 공통 점수
```

로 역할을 분리합니다.

# 10. Market Duplicate Removal

관광지 데이터에는 `시장`으로 분류된 장소가 존재하며, 별도의 전통시장 데이터에도 동일하거나 유사한 장소가 존재할 수 있습니다.

사용자가 `관광지 + 전통시장`을 동시에 선택한 경우 전통시장 DB를 시장 데이터의 기준으로 사용합니다.

따라서 관광지 데이터에서 `시장`으로 분류된 장소는 전통시장 카테고리와 의미가 중복될 경우 제거합니다.

서천군 실행 예시에서는 다음 3개 관광지 데이터가 제거되었습니다.

```text
서천특화시장임시시장
홍원항어촌계수산물판매장
장항전통시장
```

시장 장소는 `traditional_market.csv` 기반 전통시장 데이터를 사용합니다.

# 12. Time-based Recommendation

기본 여행 시작시간은 `10:00`입니다.

### 점심

```text
11:30 ~ 14:00
```

### 저녁

```text
17:30 ~ 20:00
```

### 카페·베이커리

```text
13:00 ~ 17:30
```

### 전통시장

```text
10:00 ~ 18:00
```

### 관광지

```text
09:00 ~ 17:30
```

시간대에 적합한 장소에는 가점을 부여하고 너무 이른 식사나 늦은 관광 일정에는 감점을 적용합니다.

# 13. Nearby Tourist Attraction Control

매우 가까운 관광지가 여러 개 존재할 경우 사실상 동일 관광권역을 중복 방문할 수 있습니다.

이를 방지하기 위해 관광지끼리 약 `500m` 이내에 위치하는 경우 동일 경로에 동시에 포함되는 것을 제한합니다.

---

# 14. Tourist Category Diversity

관광지만 연속해서 선택되는 경우에도 동일한 세부분류가 반복되지 않도록 관광지 다양성을 평가합니다.

예:

```text
자연공원
생태관광
랜드마크
자연경관
문화관광
```

같은 일정 내에서 서로 다른 유형의 관광지를 우선적으로 구성합니다.

# 15. Automatic Start Location

사용자가 출발 위치를 직접 입력하지 않은 경우 선택 지역의 장소 후보 위도·경도 중앙값을 임시 출발점으로 사용합니다.

```text
start_lat = 후보 장소 위도의 중앙값
start_lon = 후보 장소 경도의 중앙값
```

이를 통해 첫 번째 장소까지의 이동시간도 경로 최적화에 포함합니다.

# 20. Usage

기본 실행:

```bash
python local_on_route_recommender.py \
  --sido 충청남도 \
  --sigungu 서천군 \
  --trip day \
  --categories "맛집,관광지,카페/베이커리,전통시장"
```

시작시간 지정:

```bash
python local_on_route_recommender.py \
  --sido 충청남도 \
  --sigungu 서천군 \
  --trip day \
  --categories "맛집,관광지,카페/베이커리,전통시장" \
  --start-time 10:00
```

시군구를 입력하지 않으면 선택한 시도 내 추천점수가 가장 높은 지역을 자동으로 선택합니다.

# 21. Kakao Mobility API

Kakao Mobility REST API Key가 설정되어 있는 경우 실제 자동차 길찾기 결과를 이동시간 계산에 사용할 수 있습니다.

Windows PowerShell:

```powershell
$env:KAKAO_REST_API_KEY="YOUR_REST_API_KEY"
```

API Key가 없는 경우 위도·경도를 기반으로 이동거리와 이동시간을 추정합니다.

현재 거리 기반 추정 방식:

```text
직선거리
→ 도로거리 보정
→ 평균 이동속도 적용
→ 기본 이동시간 추가
```

API Key는 코드나 GitHub 저장소에 직접 업로드하지 않습니다.

# 24. Current Limitations

현재 모델은 다음 항목을 추가로 고도화할 수 있습니다.

- Kakao Mobility API 기반 실제 자동차 이동시간 적용
- 장소별 실제 영업시간 반영

- 여행 스타일 선택 기능
- 자연 / 문화 / 레저 / 웰니스 등 사용자 선호 반영
- 레저·웰니스 장소의 선택 여부를 사용자 취향에 따라 조절
- 숙소 데이터를 활용한 1박 2일 경로 고도화
- 전통시장 운영일 및 장날 정보 반영
